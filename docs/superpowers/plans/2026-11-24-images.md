# Images in Messages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** User messages and tool results carry text and images (`content: string | ContentPart[]`), images can be references the adapter reads at call time, and three small tool-calling issues from item 1 are fixed.

**Architecture:** The part types live in the model contract (`src/nodes/llm.ts`); two helpers (`textOf`, `resolveImages`) live in a new plugin file `src/nodes/content.ts`. The agent validates parts in its state schema and in tool results, and answers overflow calls last. The OpenAI-compatible example adapter and the two sibling packages translate parts and take a `resolveImage` option.

**Tech Stack:** TypeScript (NodeNext, strict), vitest, Zod in tests only, biome.

Spec: `docs/superpowers/specs/2026-11-24-images-design.md`.

## Global Constraints

- Zero runtime dependencies; `src/core` untouched; `src/nodes` imports only `../index.js` and `./*.js`; `src/agent` imports only `../index.js`, `../nodes/index.js` and `./*.js`.
- Only `user` and `tool` messages may carry parts; `system` and `assistant` content stays `string`. `LLMRequest` and `LLMResponse` fields are unchanged; `TRACE_VERSION` unchanged.
- Image part field names follow MCP: `{ type: "image", data, mimeType }` (base64 without a `data:` prefix) or `{ type: "image", url, mimeType? }`.
- Library text (errors, messages to the model) and code comments in English. URLs in error messages are cut to 100 characters plus `…`.
- `pnpm check` (typecheck + biome + vitest) must pass in every repo touched; `pnpm format` fixes formatting; Markdown goes through `pnpm exec biome check --write <file>`.
- taugraph work happens on branch `feat/images` (already created, spec committed as `544f5e0`). Sibling work happens on branch `feat/images` in each sibling repo; their `package.json` and `pnpm-lock.yaml` are not committed in this item.

```ts
// Helpers for adapters: the text of a message, and images given by URL turned into what they stand for.
import type { MaybePromise } from "../index.js";
import type { ChatMessage, ContentPart, ImagePart, MessageContent } from "./llm.js";
import { andThen } from "./util.js";

export interface TextOfOptions {
  /** Written in place of each image. Without it, an image is an error. */
  readonly imagePlaceholder?: string;
}

/** The text of a message's content, for adapters that send text only. Images are an error unless replaced. */
export function textOf(content: MessageContent, options: TextOfOptions = {}): string {
  if (typeof content === "string") return content;
  let text = "";
  for (const part of content) {
    if (part.type === "text") text += part.text;
    else if (options.imagePlaceholder !== undefined) text += options.imagePlaceholder;
    else {
      throw new TypeError(
        "textOf: the content has images and this adapter sends text only; pass { imagePlaceholder } to replace them",
      );
    }
  }
  return text;
}

/** Reads an image URL an adapter cannot send as it is, e.g. `media:abc` from your own store. */
export type ImageResolver = (url: string) => MaybePromise<ImagePart>;

const DATA_URL = /^data:([\w.+-]+\/[\w.+-]+);base64,([A-Za-z0-9+/]*={0,2})$/;

const shown = (url: string): string => (url.length > 100 ? `${url.slice(0, 100)}…` : url);

const isURLImage = (part: ContentPart): boolean => part.type === "image" && "url" in part;

function isImagePart(value: unknown): value is ImagePart {
  if (typeof value !== "object" || value === null) return false;
  const v = value as Record<string, unknown>;
  if (v.type !== "image") return false;
  if (typeof v.data === "string") return typeof v.mimeType === "string";
  return typeof v.url === "string" && (v.mimeType === undefined || typeof v.mimeType === "string");
}

function fromDataURL(url: string): ImagePart {
  const match = DATA_URL.exec(url);
  if (!match) throw new TypeError(`resolveImages: only base64 data: URLs are supported, got "${shown(url)}"`);
  return { type: "image", mimeType: match[1] as string, data: match[2] as string };
}

function resolveParts(parts: readonly ContentPart[], resolve: ImageResolver | undefined): MaybePromise<ContentPart[]> {
  const out: ContentPart[] = [];
  const from = (start: number): MaybePromise<ContentPart[]> => {
    for (let i = start; i < parts.length; i++) {
      const part = parts[i] as ContentPart;
      if (part.type === "text" || !("url" in part)) {
        out.push(part);
        continue;
      }
      const { url } = part;
      if (url.startsWith("data:")) {
        out.push(fromDataURL(url));
        continue;
      }
      if (!resolve) throw new TypeError(`resolveImages: no resolver for image URL "${shown(url)}"`);
      return andThen(resolve(url), (image) => {
        if (!isImagePart(image))
          throw new TypeError(`resolveImages: the resolver did not return an image for "${shown(url)}"`);
        out.push(image);
        return from(i + 1);
      });
    }
    return out;
  };
  return from(0);
}

/**
 * Replaces each image given by URL in user and tool messages: `data:` URLs become base64 images, other URLs become
 * what `resolve` returns (which may be another URL). URLs are read one after another, and the result is synchronous
 * when `resolve` is. Messages without such images are returned as the same objects.
 */
export function resolveImages(messages: readonly ChatMessage[], resolve?: ImageResolver): MaybePromise<ChatMessage[]> {
  const out: ChatMessage[] = [];
  const from = (start: number): MaybePromise<ChatMessage[]> => {
    for (let i = start; i < messages.length; i++) {
      const m = messages[i] as ChatMessage;
      if ((m.role !== "user" && m.role !== "tool") || typeof m.content === "string" || !m.content.some(isURLImage)) {
        out.push(m);
        continue;
      }
      return andThen(resolveParts(m.content, resolve), (content) => {
        out.push({ ...m, content });
        return from(i + 1);
      });
    }
    return out;
  };
  return from(0);
}
```

function checkPart(value: unknown, path: Path, issues: Issue[]): void {
  if (!isObject(value)) {
    issues.push({ message: "expected a content part object", path });
    return;
  }
  if (value.type === "text") {
    if (typeof value.text !== "string") issues.push({ message: "expected a string", path: [...path, "text"] });
    return;
  }
  if (value.type !== "image") {
    issues.push({ message: 'expected "text" or "image"', path: [...path, "type"] });
    return;
  }
  if (value.data !== undefined) {
    if (typeof value.data !== "string") issues.push({ message: "expected a string", path: [...path, "data"] });
    if (typeof value.mimeType !== "string") issues.push({ message: "expected a string", path: [...path, "mimeType"] });
    return;
  }
  if (typeof value.url !== "string")
    issues.push({ message: "expected a string (or data and mimeType)", path: [...path, "url"] });
  if (value.mimeType !== undefined && typeof value.mimeType !== "string")

    return;

/** Error answers for the calls of the last assistant message that have none: the ones beyond the per-reply limit. */
function unanswered(messages: readonly ChatMessage[]): ChatMessage[] {
  let i = messages.length - 1;
  while (i >= 0 && messages[i]?.role !== "assistant") i--;
  const last = messages[i];
  if (last?.role !== "assistant" || !last.toolCalls) return [];
  const done = new Set(messages.slice(i + 1).flatMap((m) => (m.role === "tool" ? [m.toolCallId] : [])));
  return last.toolCalls.filter((c) => !done.has(c.id)).map((c) => toolMessage(c.id, TOO_MANY, true));
}

/** URLs OpenAI takes as they are. */
const SENDABLE = /^(https?|data):/i;
const shown = (url: string): string => (url.length > 100 ? `${url.slice(0, 100)}…` : url);

function imageURL(image: ImagePart): string {
  if ("data" in image) return `data:${image.mimeType};base64,${image.data}`;
  if (!SENDABLE.test(image.url)) {
    throw new TypeError(`Image "${shown(image.url)}" must be read before sending; pass resolveImage`);
  }
  return image.url;
}

const imageOf = (image: ImagePart) => ({ type: "image_url", image_url: { url: imageURL(image) } });

const imagesIn = (content: MessageContent): ImagePart[] =>
  typeof content === "string" ? [] : content.filter((p): p is ImagePart => p.type === "image");

/** OpenAI's tool messages take text only, and have no error flag: errors say so in the text. */
function toolText(m: Extract<ChatMessage, { role: "tool" }>): string {
  const text = textOf(m.content, { imagePlaceholder: "" }) || (imagesIn(m.content).length > 0 ? "(image)" : "");
  return m.isError && !text.startsWith("Error") ? `Error: ${text}` : text;
}

/**
 * taugraph messages in OpenAI's wire format. Images from tool results go into one user message right after the
 * tool messages, since OpenAI's tool messages take text only. Image references must be read first (`resolveImage`).
 */
export function toOpenAIMessages(messages: readonly ChatMessage[]): Record<string, unknown>[] {
  const out: Record<string, unknown>[] = [];
  let toolImages: Record<string, unknown>[] = [];
  const flush = () => {
    if (toolImages.length > 0) out.push({ role: "user", content: toolImages });
    toolImages = [];
  };
  for (const m of messages) {
    if (m.role === "tool") {
      out.push({ role: "tool", tool_call_id: m.toolCallId, content: toolText(m) });
      const images = imagesIn(m.content);
      if (images.length > 0) {
        toolImages.push({ type: "text", text: `Images from tool call ${m.toolCallId}:` }, ...images.map(imageOf));
      }
      continue;
    }
    flush();
    if (m.role === "assistant" && m.toolCalls?.length) {
      out.push({
        role: "assistant",
        content: m.content === "" ? null : m.content,
        tool_calls: m.toolCalls.map((c) => ({
          id: c.id,
          type: "function",
          function: { name: c.name, arguments: JSON.stringify(c.arguments) },
        })),
      });
    } else if (m.role === "user" && typeof m.content !== "string") {
      out.push({
        role: "user",
        content: m.content.map((p) => (p.type === "text" ? { type: "text", text: p.text } : imageOf(p))),
      });
    } else {
      out.push({ role: m.role, content: m.content });
    }
  }
  flush();
  return out;
}

```md
## Content is a string or parts

User messages and tool results carry `string | ContentPart[]`, the shape OpenAI and Anthropic use, so text and images can alternate. Two additive shapes were considered. An `images` field next to a string `content` keeps old adapters compiling, but those adapters would then drop images without a word, and the order of text and images is lost. A `parts` field next to `content` keeps the order, but stores the text twice and leaves adapters to guess which one wins. The union breaks adapters at compile time instead, which is where the fix is one call: `textOf(m.content)`, which throws on images unless told what to write instead. `system` and `assistant` stay strings, because no provider takes images there in a way worth the extra cases.

Images can be references (`url: "media:abc"`) that the adapter reads at call time with `resolveImages`. The trace records every request, and the agent resends the conversation each round, so base64 inline would be stored once per round; a reference is stored as a few bytes, and replay never needs it because it does not call the model.
```

const shown = (url: string): string => (url.length > 100 ? `${url.slice(0, 100)}…` : url);

type SamplingBlock = { type: "text"; text: string } | { type: "image"; data: string; mimeType: string };

/** MCP sampling content: one text block for plain text, otherwise text and image blocks in order. */
function toSamplingContent(content: MessageContent): SamplingBlock | SamplingBlock[] {
  if (typeof content === "string") return { type: "text", text: content };
  return content.map((part): SamplingBlock => {
    if (part.type === "text") return { type: "text", text: part.text };
    if ("data" in part) return { type: "image", data: part.data, mimeType: part.mimeType };
    throw new TypeError(`MCP sampling needs image bytes, but got the URL "${shown(part.url)}"; pass resolveImage`);
  });
}
